System stats
at a glance!

Sysview is a portable, one-shot system stats viewer for Windows, Linux and macOS. The same tiny binary gives you a fast CLI overview, a live web dashboard and Prometheus metrics — with no runtime, no framework and no installer. Download once, run forever.

01 >> FEATURES

Two front-ends, one tiny process

The serve command hosts the dashboard and /metrics; the other commands render straight to your terminal. Both share the same sampler, so the numbers always agree.

[ C:\SYSVIEW> TERMINAL.EXE ]_□✕

Terminal CLI

  • Sections: sys, cpu, mem, procs, disks, net, vmstat, sensors, ports, battery — or the full overview
  • --watch live refresh, --json machine-readable output
  • Sortable & filterable process table (--sort, --top N, --filter-name)
  • Color modes auto|always|never, units iec|si|bytes
  • sysview check --cpu 90 --mem 90 scores live values against thresholds and exits non-zero — a cron / CI probe in one line
  • sysview key add mints keys with labels, expiry and a view / admin scope; sysview update self-updates with no external tools
[ DASHBOARD.EXE - FULL SCREEN ]_□✕

Web dashboard

  • Live page embedded in the binary — no build step, no Node
  • Per-core CPU sparklines, drawn crisply on HiDPI displays
  • Shared 240-sample history across every connected device
  • CPU-temperature card & load gauge, disk donuts, net/sensor mini-trends, kiosk mode with on-screen exit, retro legacy theme, snapshot JSON download
  • Interface names carry a [lan?] / [wifi?] hint, so a wired adapter is as readable as a wireless one
  • Health score badge, disk “days until full” forecast, timeline markers (M), alert pulses when CPU/mem/swap run hot, and a staleness readout
  • Listening-ports & power panel (Linux) and a device-rendered battery state, next to the usual disk donuts and net/sensor trends
  • /fleet watches several hosts at once — add them in the browser, it polls each /api/snapshot and shows up/down, CPU, memory, disk and uptime
  • Installable: a web app manifest adds the dashboard to a phone home screen and opens it standalone
  • Settings panel: manage access keys, interval, process cap, bind/interface/port and updates from the browser
[ MEM.EXE - 4 MB TOTAL?? ]_□✕

Memory-lean by design

  • Idle process: ~2 MB private RSS (was ~5 MB before v0.2.1; measured on a headless Debian 13 server)
  • Sampler sleeps after 30 s with no viewer — history ring survives
  • Command lines / environments never held between snapshots
  • systemd unit ships with a 256 MB memory ceiling
[ PROMETHEUS.EXE - SCRAPING ]_□✕

Prometheus, out of the box

  • /metrics on the same port — Prometheus text 0.0.4
  • CPU, load, memory, swap, disks, per-interface net, temp sensors, process count
  • Decoded from the cached snapshot: nothing materialized, nothing retained
  • Zero cost while idle — same 30 s pause as the dashboard
[ ALERT.EXE - SIGNAL SENT ]_□✕

Threshold alerts & webhooks

  • --alert-cpu, --alert-mem, --alert-swap, --alert-load, --alert-disk '*:90'
  • POSTs --alert-webhook on the crossing, repeats on a cooldown while hot, and once on recovery
  • Body chosen per host: ntfy raw text, Slack, Discord or generic JSON
  • Evaluated inside the existing sampler, so it adds no second thread — the POST rides a short-lived detached thread and never stalls sampling
[ TLS.EXE - LOCKED ]_□✕

Built-in HTTPS & scoped keys

  • --tls-cert / --tls-key terminates TLS in the binary itself — no reverse proxy, no new dependency
  • Keys are admin or view; a view key gets 403 on every state-changing route, so a wall display is safe to share
  • Per-IP brute-force throttling returns 429 after a small budget; a good token clears it
  • GET /health returns JSON ({ok, status, version, uptime_secs}) for uptime monitors

02 >> QUICK START

Running in three platforms

Download the binary for your OS from Releases. Verify against the SHA256SUMS on the release page, then run — that’s it.

[ MS-DOS PROMPT - SYSVIEW.EXE ]_□✕
C:\> REM download sysview-windows-x86_64.exe, then:
C:\> sysview-windows-x86_64.exe                 REM full overview
C:\> sysview-windows-x86_64.exe procs --top 20  REM top processes by CPU
C:\> sysview-windows-x86_64.exe serve           REM dashboard on :8080
C:\> sysview-windows-x86_64.exe update          REM self-update to latest
# chmod +x sysview-linux-x86_64-musl
$ ./sysview-linux-x86_64-musl                      # full overview
$ ./sysview-linux-x86_64-musl cpu --json           # CPU as JSON
$ ./sysview-linux-x86_64-musl serve --bind 0.0.0.0 --port 8080 --token "$SECRET"
$ ./sysview-linux-x86_64-musl update          # self-update to latest
# chmod +x sysview-mac-universal
$ ./sysview-mac-universal                          # full overview
$ ./sysview-mac-universal --watch --interval 1 --sort mem -r --top 15
$ ./sysview-mac-universal serve                    # dashboard on :8080
$ ./sysview-mac-universal update                   # self-update to latest

Bind beyond loopback and the startup banner prints the ready-to-open URL with your token — just scan or type it on any phone, tablet or TV in the network.

03 >> SECURITY

Safe by default, locked down by default

[ LOOPBACK.EXE ]_□✕

Loopback first

serve binds 127.0.0.1 unless you explicitly pass --bind 0.0.0.0. Nothing is reachable off-box by accident.

[ TOKEN.EXE ]_□✕

Token on every route

Set --token and every route (/, /api/snapshot, /metrics, /health) returns 401 without it. Add labelled keys with their own expiry (sysview key add --expires 30d), each scoped admin or view — a view key gets 403 on every change. Repeated bad tokens are throttled with 429. Tokens never appear in logs.

[ SYSTEMD.EXE - HARDENED ]_□✕

Hardened systemd unit

DynamicUser, ProtectSystem=strict, NoNewPrivileges, private /tmp — and Restart=always with MemoryMax=256M.

▶ NOTE: since v0.2.2 the binary can terminate HTTPS itself — serve --tls-cert fullchain.pem --tls-key privkey.pem — reusing the rustls already linked for sysview update, so there's no extra dependency. Prefer a reverse proxy (nginx / Caddy) for automatic certificates; both work.

06 >> FAQ

Questions, answered

Does it need a runtime or an installer?

No. It’s one self-contained static binary per platform. Download, chmod +x (on Unix), run. No Node, no Python, no system packages, nothing to configure.

Is it safe to expose on my LAN?

The dashboard binds loopback by default and only listens on 0.0.0.0 when you ask it to. Set a token and every route is 401 without it. The startup banner prints the ready-to-open URL with your token so you never type it by hand. Lock the port in your firewall to keep it LAN-only.

How much memory does it really use?

Around 2 MB private RSS at idle on a headless Debian 13 server, and the sampler pauses after 30 seconds with no viewer. It never retains command lines or environments between snapshots, so long-running instances don’t grow. The systemd unit adds a 256 MB ceiling as a hard cap.

Will it come back after a reboot or crash?

Yes. The systemd unit is installed enabled with WantedBy=multi-user.target and Restart=always — it starts after the network is online and revives within seconds of any crash, including kill -9.

Does it have Prometheus support?

Yes — /metrics on the same port, Prometheus text 0.0.4, token-protected, decoded from the already-cached snapshot with zero per-poll allocations.

What about alerts and monitoring?

serve --alert-cpu 90 --alert-mem 90 --alert-webhook https://ntfy.sh/my-topic posts when a threshold is crossed, again on a cooldown while it stays hot, and once on recovery — the body adapts to ntfy, Slack, Discord or generic JSON. For scripts, sysview check --cpu 90 exits non-zero on a breach, and GET /health returns JSON for an uptime monitor.

What about HTTPS?

Two options. Since v0.2.2 you can terminate TLS in the binary itself — serve --tls-cert cert.pem --tls-key key.pem (PEM, PKCS#8/PKCS#1/SEC1) — with no reverse proxy and no new dependency. Or put nginx / Caddy in front for automatic certificate management, as with any self-hosted tool.

How do I update it?

Run sysview update — it fetches the latest release over HTTPS, verifies it against the release’s SHA256SUMS, and replaces the binary in place with no git, curl or package manager. Your token and settings are kept, so existing URLs never change. update --check only looks, --force reinstalls, and there’s an update button in the dashboard Settings panel. Adding keys works the same way: sysview key add --label phone --expires 30d.

sysview version history — newest first

v0.4.0 2026-10-16
  • LAN is told apart from Wi-Fi. Wi-Fi had a marker and wired adapters had nothing. Every interface now carries a kind guessed from the OS name (eth0, enp3s0, Ethernet → LAN; wlan0, Wi-Fi → Wi-Fi) and shows it as a [lan?] / [wifi?] hint in sysview net, the --interface error list, the dashboard network table and the settings picker.
  • Honest about what a name cannot say. macOS en0 (Ethernet on desktops, the Wi-Fi radio on most laptops), bridges, tunnels, veth pairs and Windows virtual switches stay unmarked instead of being guessed wrong, nothing is filtered on the kind, and metric labels stay bare so scrapers keep working.
v0.3.1 2026-10-16
  • serve --qr is quiet when the code cannot be drawn. The symbol is built from background colours; a redirected log, a dumb TERM or NO_COLOR now gets one line pointing at the URL instead of about twenty-five blank rows, while a real terminal still gets the code.
  • The machine-wide service keeps its documented ceiling. sysview service install --system writes MemoryMax=256M, as scripts/setup-debian.sh always has; the per-user unit is unchanged.
v0.3.0 2026-10-16
  • sysview top. A full-screen process monitor that stays open: c/m/p/n sort, r reverses, +/- resize, q quits. No new dependency (stty on Unix, the C runtime on Windows), and the terminal is restored on exit.
  • sysview service install|uninstall|status. Registers the dashboard with whatever the host already runs - a hardened systemd unit, a launchd plist, or a Windows scheduled task - with the token kept where the platform keeps secrets. --print shows the unit and the commands without applying anything; --system installs machine-wide.
  • sysview export. Prometheus text or CSV for host, disks, processes or network, rendered by the same code as /metrics, so the CLI and the endpoint cannot disagree.
  • sysview diff BEFORE [AFTER]. Host-level comparison between two snapshots or against the live host, including a reboot flag and mounts/interfaces that appeared or disappeared. Reads snapshots even when PowerShell wrote them as UTF-16.
  • sysview cgroup and sysview gpu (Linux). The cgroup v2 quota, counters and PSI stall pressure the process actually runs under - what a host-wide view cannot show in a container - and the DRM cards the kernel reports, with only the figures sysfs really has.
  • serve --history-file appends a JSON line per sample and replays the tail on start (trimmed once it has grown past several windows, so it cannot fill a disk); /api/history serves the rolling window alone; serve --qr prints a scannable code for the LAN URL.
v0.2.4 2026-10-16
  • Windows output cleaned up. No more rows that only restate another row — sys drops Kernel when it merely repeats the OS build, mem drops Free when it equals Available, and vmstat omits Run/Block (Windows has no run queue). vmstat --json reports null for both counts.
  • Honest check exit codes. 0 pass, 1 breach, 2 nothing evaluated — a probe with nothing to compare (no threshold, or one this platform cannot evaluate) explains itself and exits 2 instead of a silent 0.
  • Release notes always match the changelog. The publish job now fails when a tag has no CHANGELOG.md section, so a release can no longer fall back to auto-generated commit lists; the back catalogue was republished from the changelog.
v0.2.3 2026-10-15
  • Leaner polling. The dashboard's per-tick snapshot now ranks raw process handles and only builds the rows it actually shows, and resolves process owners by uid instead of a per-process string key — fewer allocations on the hottest loop, with identical output.
  • Dependency refresh. Build-time crates updated; no runtime or behaviour change.
v0.2.2 2026-10-11
  • Threshold alerts & webhooks. serve can watch CPU, memory, swap, load and any mount (--alert-cpu/--alert-mem/--alert-swap/--alert-load/--alert-disk '*:90') and POST on the crossing, on a repeating cooldown while it stays hot, and once on recovery. The body adapts per host (ntfy, Slack, Discord, generic JSON), and the POST rides a short-lived detached thread so sampling never stalls.

  • JSON /health and sysview check. A small JSON probe for uptime monitors, plus a one-shot sysview check --cpu 90 --mem 90 that exits non-zero on a breach for cron / CI.
  • Built-in HTTPS. serve --tls-cert cert.pem --tls-key key.pem terminates TLS in the binary (PKCS#8/PKCS#1/SEC1), reusing the rustls already linked for sysview update — no reverse proxy, no new dependency.
  • Fleet page & installable app. /fleet watches several hosts at once (the host list lives in the browser, so the server stores nothing); opt-in --cors lets a fleet page on another origin poll a host; a web app manifest makes the dashboard installable.
  • Listening ports & battery. sysview ports and sysview battery (plus a dashboard panel) read Linux /proc/net and /sys/class/power_supply — bounded and allocation-light, so the idle footprint is unchanged.
v0.2.1 2026-10-11
